# Story Premises

- Editable premises live under `PROJECT_BIONIC/STORY_CANVAS-PREMISES/` and use `Story - [STORY-###].md`.
- Production snapshots live as the corresponding Story's `VSSA_PREMISE` under `PROJECT_BIONIC/GENERATED-STORY-ARTIFACTS/`.
- The first line is exactly `Story-ID: STORY-###`, followed by one blank line and the English premise.
- A new ID is the lowest unused positive three-digit sequence beginning with `STORY-001`.
- Existing valid nonnumeric Story IDs remain readable and producible; every newly saved Story uses `STORY-###`.
- The premise is a flexible creative canvas, not a finished Story and not a ComfyUI prompt.
- Include only the Story facts and direction Team Master wants the generated package to preserve.
- Short premises permit broad compatible invention. Detailed premises constrain invention without removing useful creative development.
- Saving a new premise requires an approved ID. Replacing an existing premise requires a clear request and optimistic hash validation.
- Before production, the exact saved premise must be displayed in full and approved; production validates the same premise hash.
